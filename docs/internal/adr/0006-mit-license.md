# ADR-0006: ライセンスは MIT とする

- 状態: Accepted
- 日付: 2026-06-05
- 関連: `LICENSE`、`docs/internal/tasks/task.md` TASK-110

## Context

OSS のライセンス候補は次が代表的。

1. **MIT**: 利用者側の義務が最小限。商用利用 / 改変 / 再配布 / サブライセンス可。著作権表示と免責だけ要求
2. **Apache-2.0**: MIT の許可範囲に加え、明示的な特許権付与とリタリエーション条項を含む
3. **GPL / LGPL**: 強い copyleft。本プロジェクトの目的（embedding 容易性）と整合しない

## Decision

**MIT** を採用する。

主な理由:

- **採用障壁の最小化**: 商用 SaaS / クローズドな社内ツールへの埋め込みが法務確認なしで受け入れられやすく、利用者の裾野を広げられる
- **互換性の広さ**: Apache-2.0 / BSD / ISC 等のほぼすべての OSS ライセンスと組み合わせ可能で、サブライセンスや再配布も容易
- **運用負荷の低さ**: `NOTICE` ファイル維持や貢献者ライセンス契約（CLA）の整備など、Apache-2.0 系で必要になる事務作業を省略できる
- **本プロジェクトの優先度**: 特許防衛より OSS としての普及・組み込み容易性を重視する。利用者が特許保護を強く欲する場合は、依存元の Apache-2.0 ライセンスで間接的にカバーされる
- **認知度**: 開発者コミュニティーでの MIT 認知がもっとも高く、ライセンス選定の説明コストが小さい

## Consequences

良い影響:

- 商用 SaaS / クローズドな社内ツールでの埋め込みが容易
- 他ライセンスとの互換性が広く、サブライセンスが容易
- ライセンス文書が短く読みやすい

悪い影響:

- 特許権の明示的な付与・防衛条項がない
- Apache-2.0 と組み合わせるとき、依存先の `NOTICE` を維持する責務は依存利用者側に残る

## Alternatives Considered

- **Apache-2.0**: 特許明示権で勝るが、本プロジェクトでは特許防衛優先度が低い。導入の手軽さを優先して MIT を選ぶ
- **dual license（MIT or Apache-2.0）**: 二系統での合意維持・ファイルヘッダー記述の運用負荷がリリース時点では見合わない
- **BSD-3-Clause**: MIT と機能差が小さく、ネームバリュー的に MIT の方が認知が高い
