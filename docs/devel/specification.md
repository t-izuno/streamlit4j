# streamlit4j 仕様書

> ステータス: ドラフト v0.1
>
> 関連ドキュメント: 要件は `requirements.md`、設計は `design.md`、実行計画は `tasks/task.md`

本書は streamlit4j の外部仕様（API サーフェス・プロトコル・要素カタログ）を定義する。
内部実装方式（ID 生成アルゴリズム・差分計算・スレッドモデル等）は `design.md` を参照する。

## 1. API ファサード仕様

### 1.1 St ファサード

- `St` ファサードに Streamlit 互換の命名でメソッドを並べる
- 入力系メソッドは現在値を直接返す
- 表示系メソッドは要素ハンドルを返す
- よく使う組み合わせは直接戻り値オーバーロードを用意し、詳細指定はビルダーで補う
- 終端メソッド名（`show()` / `render()` / `use()` 等）は未決定（`design.md` 10 章参照）

### 1.2 サンプルコード

```java
import io.streamlit4j.St;

public class App {
    public static void main(String[] args) {
        St.title("売上ダッシュボード");

        // 直接戻り値オーバーロード（簡潔パス）
        int year = St.slider("対象年", 2018, 2026, 2025);

        var df = SalesRepository.byYear(year);
        St.metric("総売上", df.total());
        St.lineChart(df.monthly());

        // ビルダー（詳細指定パス）
        String region = St.selectbox("地域")
                          .options("東日本", "西日本", "全国")
                          .key("region")
                          .show();

        if (St.button("CSV を再集計")) {
            St.toast("再集計しました");
        }
    }
}
```

### 1.3 エントリポイント定義形式

ユーザーは以下のいずれかでエントリポイントを 1 つ定義する。

- `void main()` 相当のメソッド
- `St.app(...)` に渡すラムダ

### 1.4 制御 API

- `St.rerun()`: 明示的な再実行をトリガーする
- `St.stop()`: 現在の再実行を中断する

### 1.5 ウィジェット同一性

- 明示キー優先 + 呼び出し位置由来の決定的 ID で同一性を確定する
- `key` パラメーターは任意指定可能

## 2. トランスポートとプロトコル仕様

### 2.1 通信路

- v1 は JSON エンベロープを採用する
- バージョン付きエンベロープでメッセージ種別を明示する
- 標準トランスポートは SSE + HTTP POST とする（ADR-0012）
- WebSocket は互換トランスポートとして残す
- トランスポートは差し替え可能な境界を持つ
- SSE 構成では、サーバーからブラウザーへの逐次配信は SSE（`text/event-stream`）、
  ブラウザーからサーバーへの操作は通常の HTTP POST を使う
- WebSocket 構成では、サーバーからブラウザーへの差分配信とブラウザーからサーバーへの
  操作を同一接続上の JSON メッセージとして扱う

### 2.2 メッセージ例（render_delta）

```json
{
  "v": 1,
  "type": "render_delta",
  "sessionId": "s-8f3a",
  "seq": 42,
  "patches": [
    {
      "op": "replace",
      "path": "main/0",
      "node": {
        "kind": "slider",
        "id": "w_year",
        "props": { "label": "対象年", "min": 2018, "max": 2026, "value": 2025 }
      }
    }
  ]
}
```

### 2.3 メッセージ種別

サーバーからブラウザーへ送るメッセージ:

- `session_init`: セッション確立・初期レンダー
- `render_delta`: サーバーからクライアントへの差分
- `download_ready`: ダウンロード準備完了
- `error`: 実行エラーの通知

ブラウザーからサーバーへ送るメッセージ:

- `widget_event`: クライアントからサーバーへの値変更・ボタン押下
- `rerun_request`: 明示再実行
- `file_upload`: ファイルアップロード

## 3. レンダーツリーノード仕様

- ノードは `kind` / `id` / `props` / `children` を持つ不変表現とする
- `kind` は要素種別の識別子
- `id` はウィジェット同一性を表す決定的 ID
- `props` は要素固有のパラメーター集合
- `children` は子ノードリスト

## 4. 要素カタログ仕様

### 4.1 要素定義の 3 点セット

各要素は以下の 3 点セットで定義する。

- Java 側ビルダー API
- プロトコル上のノード表現（`kind` と `props`）
- フロント描画コンポーネント

### 4.2 入力系ウィジェット

- `slider` / `text_input` / `number_input` / `selectbox` / `multiselect`
- `checkbox` / `radio` / `button` / `date_input` / `time_input`
- `color_picker` / `select_slider` / `text_area` / `data_editor`
- `file_uploader`

### 4.3 表示系要素

- `write` / `markdown` / `title` / `header` / `subheader` / `caption`
- `metric` / `dataframe` / `table` / `json` / `code` / `latex` / `html`
- `image` / `audio` / `video` / `divider`
- `toast` / `progress` / `spinner` / `status`
- チャート: `line_chart` / `bar_chart` / `area_chart` / `scatter_chart`

### 4.4 レイアウト系

- `columns` / `container` / `expander` / `tabs` / `sidebar`
- `empty` 相当のプレースホルダー

## 5. セッション状態 API 仕様

- `session_state` 相当の Key-Value ストアを提供する
- 型付きアクセサーで `String` キーと型を指定して安全に取得・設定する
- セッションのライフサイクルリスナー（生成・タイムアウト・破棄）を登録できる

## 6. マルチページ仕様

ページ宣言方法を 2 系統サポートする。既定方式は未決定（`design.md` 10 章参照）。

- 規約ベース: 特定パッケージ・ディレクトリのクラスを自動探索する
- 明示登録ベース: `St.pages(...)` にページ定義を渡す

ナビゲーション機構として、ページ間ナビゲーション UI と URL ディープリンクを提供する。

## 7. フォーム仕様

- `form` コンテナー内のウィジェットは送信ボタン押下まで再実行を抑制する
- 送信時にまとめて値を確定し、1 回の再実行で反映する

## 8. キャッシュ仕様

### 8.1 種別

- データキャッシュ: 戻り値の再利用
- リソースキャッシュ: コネクション等の共有

### 8.2 指定方式

アノテーションまたはラッパー関数の両対応を検討する。
既定方式は未決定（`design.md` 10 章参照）。

### 8.3 無効化

- 無効化キー（引数ハッシュ）を指定可能
- TTL を指定可能

## 9. カスタムコンポーネント仕様

### 9.1 種別

- 「インプロセス component」のみ提供: 同梱バンドルに React 部品を登録
- iframe 隔離方式は採用しない（理由は `design.md` 9 章参照）

### 9.2 Java 側 API

- コンポーネントの引数・戻り値を型で宣言する

## 10. テーマ仕様

- ライト / ダーク / カスタムカラーの 3 種を設定で切り替え可能にする
- カラーパレットは独自視覚アイデンティティーに基づく（Streamlit 公式パレット流用禁止）

## 11. ファイル入出力仕様

### 11.1 アップロード

- サイズ上限を設定可能
- MIME 制限を設定可能
- ストリーミング受信に対応

### 11.2 ダウンロード

## 12. 開発体験仕様

- ソース変更検知時、ブラウザーを自動リロードする
- エラーは画面上にスタックトレース付きで表示する
- CLI 起動コマンド: `streamlit4j run App.java`

## 13. 実行形態仕様

### 13.1 スタンドアロン CLI

## 14. LLM UI 仕様

LLM / AI エージェントの操作 UI は、通常の Streamlit 型 UI と同じ再実行モデル上に
構築する。アプリコードは低レベルトランスポートを意識せず、チャット要素と
トークン列を扱う。

### 14.1 チャット API

- `St.chatMessage(role, content)`: 確定済みメッセージを表示する
- `St.chatInput(label)`: ユーザー入力欄を表示し、送信された文字列を返す
- `St.writeStream(tokens)`: `Iterable<String>` / `Stream<String>` / `Flow.Publisher<String>`
  相当のトークン列を逐次表示する
- `St.chatControls()`: 生成中の停止、リトライ、編集再生成の標準操作を表示する
- チャット API は内部的に `chat_message` / `chat_input` / `chat_stream` /
  `chat_controls` ノードを生成する

### 14.2 生成中操作

- 停止: 生成中セッションにキャンセルを通知し、以後のトークンを破棄する
- リトライ: 同じユーザー入力と会話履歴で直近の assistant メッセージを再生成する
- 編集再生成: 指定したユーザー入力を書き換え、以降の assistant メッセージを破棄して
  再生成する
- いずれの操作も UI 表示だけでなく、サーバー側の生成状態に反映する

### 14.3 未完 Markdown 耐性

- 生成途中の Markdown は、最終文字列が未完でも DOM 構造を破綻させない
- コードフェンス、表、リスト、数式の途中断片を受け取っても、表示領域外へ
  レイアウトが崩れない
- 最終トークン受信後は通常の Markdown 表示と同じ構造へ収束する

### 14.4 リッチ表示

- チャットメッセージ内にコード、表、数式、添付ファイル、ツール実行結果を表示できる
- ツール実行結果は `tool_result` ノードとして、タイトル、ステータス、本文、
  任意の子ノードを持てる
- カスタムコンポーネントは通常の `component` ノードとしてチャットメッセージ内に
  配置できる

### 14.5 Fake LLM

受入テストとサンプル用に、外部ネットワークへ接続しない Fake LLM を提供する。

- 固定トークン列を一定間隔で返す
- トークン列には Markdown の途中断片、コードフェンス、表、数式を含める
- 停止要求を受けた場合は以後のトークン送出を止め、キャンセル済みイベントを記録する
- リトライと編集再生成では、入力と履歴から決定的に同じ結果を返す

## 15. LLM UI 受入テスト仕様

### 15.1 トランスポート契約

SSE + HTTP POST と WebSocket は同じ JSON エンベロープを扱う。
テストでは同じ Fake LLM シナリオを両トランスポートで実行し、差分を比較する。

- サーバーからブラウザーへの `session_init` / `render_delta` / `error` が届く
- ブラウザーからサーバーへの `widget_event` / `rerun_request` / `file_upload` が届く
- 再接続後に最新レンダーツリーへ復帰できる
- 認証付き環境でセッションが維持される
- 生成中キャンセルがサーバー側に到達する

### 15.2 Playwright 受入シナリオ

- 実ブラウザーで Fake LLM チャットサンプルを開く
- 入力送信後、トークンが段階的に増えることを DOM で確認する
- 未完 Markdown の中間状態でコードフェンス、表、数式がレイアウト破綻しないことを確認する
- 停止ボタン押下後、DOM の生成状態とサーバー側キャンセルイベントを確認する
- リトライで直近 assistant メッセージが再生成されることを確認する
- ユーザー入力の編集後再生成で、編集後入力だけが新しい応答に使われることを確認する

### 15.3 CLI 成果物スモーク

- packaged jar または CLI でサンプルを起動できる
- `GET /` が 200 応答を返し、フロント静的アセットを配信できる
- 設定されたトランスポートで初期接続できる
- 初期レンダー完了後、チャット入力が操作可能になる
